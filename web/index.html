场景 4：同名客户订单聚合

同时用客户名称和下单城市做筛选条件，让同一个展示名称下的订单数可以被正确聚合。

原公式

=LET( k,TRIM($C3), tC,ARRAYFORMULA(TRIM('客户名称-客户下单城市 (定期更新）'!$C$3:$C$197)), tD,ARRAYFORMULA(TRIM('客户名称-客户下单城市 (定期更新）'!$D$3:$D$197)), tE,ARRAYFORMULA(TRIM('客户名称-客户下单城市 (定期更新）'!$E$3:$E$197)), clientKeys,UNIQUE(FILTER(tD,tC=k,tD<>"")), addrList,UNIQUE(FILTER(tE,tC=k,tE<>"")), dataWeek,ARRAYFORMULA(TRIM('BI数据源处理'!$A$3:$A$50000)), dataClient,ARRAYFORMULA(TRIM('BI数据源处理'!$F$3:$F$50000)), dataAddr,ARRAYFORMULA(TRIM('BI数据源处理'!$D$3:$D$50000)), weekOk,ARRAYFORMULA(dataWeek=TRIM($A$2)), clientOk,ARRAYFORMULA(ISNUMBER(MATCH(dataClient,clientKeys,0))), addrOk,ARRAYFORMULA(ISNUMBER(MATCH(dataAddr,addrList,0))), IF( k="", "", SUMPRODUCT( N(weekOk), N(clientOk), N(addrOk) ) ) )

找出这个客户对应的所有下单城市/地址。

5. 三个条件判断weekOk / clientOk / addrOk

周次、客户、地址逐行判断。

6. 聚合计数SUMPRODUCT

三关都通过才计 1。

场景 5：改变表格呈现方式

把原表中横向按日期分组登记的数据，转换成目标表里“日期 + 客户 + 指标”的明细呈现方式。

先别看公式：它其实是在找一个坐标

目标表里的每一个单元格，都可以理解成向原表提一个问题：

在原表里，客户 B2 在日期 A2 下面的指标 D1，是多少？
A2：日期

决定去原表第 2 行找哪个横向日期块。

找日期块
B2：客户

决定去原表 B 列找哪一行。

找客户行
D1：指标

决定在当前日期块下面找哪一个指标列。

找指标列

用一个小表看懂列号怎么来

假设原表里 `6月16日` 从第 10 列开始，并且每个日期有 5 个指标：

真实列号 第 10 列 第 11 列 第 12 列 第 13 列 第 14 列
第 2 行日期6月16日这一组日期块
第 3 行指标揽收数量上网当日上网非当日CMR上网率
块内位置12345

如果目标表要找 `CMR`，它在日期块内是第 4 个指标，所以真实列号就是：

日期块起始列 10 + 块内位置 4 - 1 = 第 13 列

为什么减 1：因为起始列本身已经是第 1 个指标，不能再多加一次。

把长公式翻译成 3 个积木

积木 公式片段 中文

核心流程

1. 找客户行MATCH($B2,原表B列,0)

用客户名定位原表里的行号。

2. 找日期块MATCH($A2,原表第2行,0)

用日期定位横向日期分组的起始列。

3. 圈住指标区INDEX(...):INDEX(...+4)

4. 找块内指标MATCH(D$1,指标区,0)

找目标表当前列标题在日期块里的位置。

5. 算真实列日期起点 + 块内位置 - 1

把块内位置换成原表真实列号。

6. 交叉取数INDEX(原表,行号,列号)

行列交叉，取回结果。

核心记忆：普通公式处理一个单元格，`ARRAYFORMULA` 像流水线，一次处理一整列。

=ARRAYFORMULA(要批量执行的公式)
写法处理对象效果
TRIM(C3)一个单元格只清洗 C3。
ARRAYFORMULA(TRIM(C3:C197))一整列批量清洗 C3:C197。

场景 4 案例

dataClient,ARRAYFORMULA(TRIM('BI数据源处理'!$F$3:$F$50000))

这表示：把 BI 数据源 F3:F50000 的客户名称整列去空格，得到一列干净的客户名，后面再拿去做 `MATCH` 判断。

适合什么时候用例子
整列清洗ARRAYFORMULA(TRIM(范围))
整列判断ARRAYFORMULA(dataWeek=TRIM($A$2))
整列匹配ARRAYFORMULA(ISNUMBER(MATCH(dataClient,clientKeys,0)))

MATCH：找位置号

核心记忆：`MATCH` 不返回内容，只返回“第几个”。

=MATCH(查找值, 查找范围, 0)
角色公式例子返回什么
找客户行MATCH($B2,客户列,0)客户在第几行。
找日期块MATCH($A2,日期标题行,0)日期从第几列开始。
找指标位置MATCH(D$1,日期块标题范围,0)指标在日期块里第几格。
判断是否在清单里ISNUMBER(MATCH(dataClient,clientKeys,0))找到为 TRUE，找不到为 FALSE。

易错点：`0` 表示精确匹配。做客户名、地址、指标标题匹配时，通常都应该用 `0`。

MATCH + ISNUMBER：判断是否在清单里

核心记忆：`MATCH` 负责查名单，查到会返回位置号；`ISNUMBER` 负责判断这个位置号是不是数字。合起来就是“是否存在于清单中”。

=ISNUMBER(MATCH(要检查的值, 清单范围, 0))
结果MATCH 会怎样ISNUMBER 后含义
找到了返回 1、2、3 这种位置号TRUE这个值在清单里。
没找到返回错误FALSE这个值不在清单里。

场景 4 案例

clientOk,ARRAYFORMULA(ISNUMBER(MATCH(dataClient,clientKeys,0)))

这段的意思是：逐行检查 BI 数据源里的客户名 `dataClient`，是否存在于映射表生成的客户清单 `clientKeys` 里。

需求公式模式

判断地址是否属于某个地址清单ISNUMBER(MATCH(地址,地址清单,0))
配合 `SUMPRODUCT` 做多条件计数SUMPRODUCT(N(weekOk),N(clientOk),N(addrOk))

INDIRECT + SUBSTITUTE：动态引用工作表

核心记忆：`SUBSTITUTE` 负责把工作表名处理安全，`INDIRECT` 负责把文本地址变成真正引用。

=INDIRECT("'"&SUBSTITUTE(表名,"'","''")&"'!$Y:$Y")
函数作用场景 7 里的角色
SUBSTITUTE替换文本。把表名里的 ' 替换成 ''。
&拼接文本。拼出 '表名'!$Y:$Y。
INDIRECT文本转引用。真正读取该工作表的 Y 列或 X 列。

单独看 SUBSTITUTE

=SUBSTITUTE("L'OREAL","'","''")

结果是 L''OREAL。这是为了避免工作表名里自带的单引号破坏引用格式。

单独看 INDIRECT

=INDIRECT("'客户A'!$Y:$Y")

这会真正引用 `客户A` 工作表的 Y 列。没有 `INDIRECT` 时，`'客户A'!$Y:$Y` 只是拼出来的一段文字。

QUERY + FILTER：先筛选明细，再生成汇总表

核心记忆：FILTER 负责决定“哪些行可以进来”，QUERY 负责决定“进来以后如何分组、计数和展示”。

基础语法

=QUERY(数据区域, 查询语句, 标题行数)
=FILTER(返回区域, 条件1, 条件2, ...)
=QUERY( FILTER(数据区域,筛选条件), "select ... group by ... label ...", 0 )
参数作用当前案例
数据区域QUERY 要处理的临时表。{城市列,BI客户列}
查询语句规定输出列、分组方式、统计方式和标题。select Col1,Col2,count(Col1)...
标题行数输入数据顶部有几行标题。0，因为 FILTER 结果第一行就是数据。
FILTER 条件只有所有条件均为 TRUE 的行才保留。周次等于 A2，城市不为空。

场景 9 实战公式

=QUERY( FILTER( {TRIM('BI数据源处理 【周维度】'!D4:D60855),TRIM('BI数据源处理 【周维度】'!F4:F60855)}, TRIM('BI数据源处理 【周维度】'!A4:A60855)=TRIM($A$2), 'BI数据源处理 【周维度】'!D4:D60855<>"" ), "select Col1,Col2,count(Col1) group by Col1,Col2 label Col1 '',Col2 '',count(Col1) ''", 0 )

从里往外读

层级作用结果
{D列,F列}把不相邻的城市列和 BI 客户列横向拼接。临时两列表。
TRIM去除首尾隐藏空格。干净的城市和客户名称。
FILTER只保留当前周且城市不为空的数据。当前周逐票明细。
QUERY按城市和 BI 客户分组计数。城市＋客户＋票数汇总表。

常见错误

错误原因处理
FILTER 范围大小不同返回区域和条件区域行数不一致。所有范围统一使用 4:60855。
Col1、Col2 写反Col 编号由大括号里的排列顺序决定。{城市,客户} 中城市是 Col1，客户是 Col2。
结果多出标题行最后参数或 label 设置不正确。无标题输入用 0，自定义标题时可用 label。
没有结果时报 #N/AFILTER 找不到符合条件的行。需要时外层增加 IFNA(...,"无数据")。

GROUP BY：把相同组合折叠成一行

先澄清：GROUP BY 不是一个独立的 Excel/Google Sheets 函数，而是 QUERY 查询语句中的分组子句。

核心记忆：按照哪些列分组，就把这些列内容相同的记录放进同一个篮子，再对每个篮子计数或求和。

基础写法

=QUERY(数据,"select Col1,count(Col1) group by Col1",0)
=QUERY(数据,"select Col1,Col2,count(Col1) group by Col1,Col2",0)
写法分组颗粒度适用场景
group by Col1只按城市分组。查看每个城市总票数。
group by Col1,Col2按城市＋BI客户组合分组。区分同一城市的不同客户。
group by Col1,Col2,Col3按三个字段的组合分组。城市＋客户＋渠道等更细颗粒度。

为什么当前案例必须分组两列

城市BI客户票数
LISSESCIRRO-Temu-BT-PU66
LISSESGOODCANG-FR452

如果只写 group by Col1，两组 LISSES 会被合并成 518 票，看不出其中有两个 BI 客户；写 group by Col1,Col2 才能保留真实组合。

SELECT 与 GROUP BY 的对应规则

在 select 中出现、但没有被 count、sum、avg 等聚合函数处理的列，通常也必须出现在 group by 中。

select Col1,Col2,count(Col1) group by Col1,Col2
聚合写法作用
count(Col1)统计每个分组有多少行。
sum(Col3)汇总每个分组的金额或重量。
avg(Col3)计算每个分组的平均值。
max(Col3)取得每个分组的最大值。

一句话记忆

SELECT 决定我要展示什么，GROUP BY 决定哪些记录算同一组，COUNT/SUM 决定每组怎么算。

MAP + LAMBDA：对多列数据逐行执行同一套逻辑

核心记忆：MAP 负责把每一行送进加工台，LAMBDA 给当前行的数据起名字，并规定每一行怎么计算。

基础语法

=MAP(数组1, LAMBDA(当前值, 对当前值的计算))
=MAP(数组1,数组2,LAMBDA(值1,值2,对两个当前值的计算))
组成部分作用当前案例
B33:B第一个输入数组。发货城市列。
C33:C第二个输入数组。BI客户列。
LAMBDA(city,client,...)给当前行的两个值命名。当前城市叫 city，当前客户叫 client。
LAMBDA 最后部分定义每一行返回什么。返回映射客户名或 NA。

场景 9 实战公式

=MAP(B33:B,C33:C,LAMBDA(city,client, IF(city="","", IFNA( TEXTJOIN(" / ",TRUE,UNIQUE(FILTER( '客户名称-客户下单城市 (定期更新）'!C$3:C$1000, LOWER(TRIM('客户名称-客户下单城市 (定期更新）'!D$3:D$1000))=LOWER(TRIM(client)), LOWER(TRIM('客户名称-客户下单城市 (定期更新）'!E$3:E$1000))=LOWER(TRIM(city)) ))), "NA" ) ) ))

从外到内理解

公式层级作用记忆
MAP逐行遍历城市和 BI 客户两列。流水线传送带。
LAMBDA(city,client,...)定义当前行变量和处理方法。给原料起名字、写加工说明。
IF(city="","",...)空行不计算。没原料就停机。
FILTER同时按 BI 客户和城市筛映射表。两道条件筛子。
UNIQUE清除重复的客户名称。同名只保留一次。
TEXTJOIN(" / ",TRUE,...)多个有效映射用斜杠拼接。多个答案都展示。
IFNA(...,"NA")完全找不到时显示 NA。缺映射要显性报警。

MAP 和普通向下填充的区别

方式特点适合场景
普通行公式每行一个公式，需要向下复制。数据行数固定、逻辑简单。
MAP + LAMBDA一个公式自动生成整列结果。QUERY 结果行数会随周次变化。

常见错误

错误原因处理
LAMBDA 参数数量不一致MAP 输入两列，但 LAMBDA 只定义一个名字。两列输入必须写两个参数，如 city,client。
结果无法展开公式下方已有手工内容。清空输出区域，让数组公式自动溢出。
大小写或空格导致找不到源表文本不规范。比较两边都使用 LOWER(TRIM(...))。
只返回第一个结果使用 XLOOKUP 而不是 FILTER。用 FILTER + UNIQUE + TEXTJOIN 保留全部有效映射。

1确认输入
